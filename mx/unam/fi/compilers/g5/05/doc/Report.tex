\section{Introduction}
Compilers are essential tools in computer science, acting as translators that transform high-level source code into low-level machine instructions \cite{aho2006compilers}. This transformation process is divided into several phases: Lexical Analysis, Syntax Analysis, Semantic Analysis, Intermediate Code Generation, Code Optimization, and Target Code Generation.

This report focuses exclusively on the Lexical Analysis phase. Its primary function is to examine the source code and break it down into basic units called tokens. These tokens represent meaningful elements of the language, such as keywords, identifiers, operators, constants, and punctuation marks \cite{10.5555/576122}.

The objective of this project is to develop an automated Lexical Analyzer capable of processing text input and identifying these elements. By removing irrelevant components like whitespace and comments, the system simplifies the complexity for subsequent phases. The final system not only categorizes each token but also provides a structured representation and a total count of detected elements, ensuring a robust foundation for the compilation process.

\section{Theoretical Framework}
Lexical analysis is the first contact between the source code and the compiler. The analyzer reads the input stream character by character and groups them into meaningful sequences called lexemes. Each lexeme is then mapped to a specific token type, which serves as the input for the syntax analyzer.

To achieve this, lexical analyzers utilize pattern recognition mechanisms, typically defined through regular expressions. These formal descriptions allow the system to differentiate between an identifier (like a variable name) and a reserved keyword (like \textit{int} or \textit{print}). 

In this project, we explored both manual implementation and the use of specialized libraries. While manual implementation provides a deep understanding of the scanning process, libraries like RPLY offer optimized memory management and scalability. This approach adheres to modern software engineering standards, such as ISO/IEC/IEEE 15939, ensuring that the lexer acts as an efficient filter \cite{ISO}.

\section{Development}
The implementation followed an incremental methodology to showcase the evolution from a basic script to a professional-grade software component. We developed a centralized hub, \textit{executable.py}, which allows the user to select between three distinct versions of the Lexer.

\subsection{Incremental Implementation Levels}
\begin{itemize}
    \item \textbf{Level 1: Simple Lexer.} A fundamental version focused on basic pattern recognition using standard regular expression modules. It identifies 53 different tokens.
    \item \textbf{Level 2: Enhanced Lexer.} This version optimized output formatting. It ensures all token categories are displayed in lowercase and provides a precise total count.
    \item \textbf{Level 3: Professional Lexer (RPLY).} The final stage involved migrating to the RPLY library. This implementation compiles lexical rules upon instantiation, significantly improving performance.
\end{itemize}

\subsection{Special Features and Functions}
The system handles complex identifiers, including the \$ symbol. The engine supports 28 keywords, 14 operators, and 9 punctuation marks, totaling 53 patterns. Furthermore, the system includes modular functions to read input from terminal strings or external files.

\section{Conclusions}
The development of this Lexical Analyzer demonstrated the practical application of theoretical concepts such as regular expressions and finite automata. By implementing an incremental methodology, the team transitioned from a functional script to a modular architecture.

The use of the RPLY library was a decisive factor, fulfilling the 53-token requirement and providing a robust platform for future syntax analysis \cite{Verma}. This experience highlights that understanding the first phase of compilation is crucial for software engineers, as it establishes the principles of data validation and efficient processing \cite{Afzaal}.
